About SolarSense

SolarSense monitors a solar plant at inverter level. For every 15-minute reading it predicts the power each inverter should produce for the measured sunlight and panel temperature, compares it with the actual output, and raises an alert when the gap points to a fault. Each alert states the reason, the evidence, the energy and money lost, and the recommended action.

Problem addressed

Plant output is usually reviewed as a daily or monthly total, so a tripped inverter or a weak string can go unnoticed until the losses show up on the bill. Low output alone is not enough to act on: it has to be separated into what the weather caused and what a technician can fix.

How it works

The pipeline computes everything in advance; the website only displays results. The AI never decides alone: clear rules raise every alert and explain why.

What it detects

Fault typeHow it is detectedLikely causeRecommended action
Inverter tripStrong sunlight but AC output near zero for several readingsInverter fault, grid tripSend a technician to restart / inspect
UnderperformanceOutput well below expected for a sustained period and below neighbouring invertersFailed string, shading, wiringInspect strings and connectors
Degradation / soilingDaily performance ratio trending down relative to peersDust, ageing modulesSchedule cleaning
Data gapReadings missing during daylightLogger or network failureCheck communication link
OverheatingPanel temperature far above ambient with reduced efficiencyPoor ventilation, hotspotsThermal inspection
Sensor / data issuePhysically impossible values (e.g. DC-to-AC ratio)Miscalibrated sensorRecalibrate sensor

Losses are split into natural (clouds, heat) and fixable (faults), so weather is not mistaken for a fault. Exact thresholds are listed under Assumptions.

Data required for a new plant

Inverter readingsTimestamp, inverter ID, DC power, AC power (15-minute interval or finer)
Weather sensorIrradiation and module temperature (ambient optional)
ConfigurationTariff (₹/kWh), alert thresholds, plant names in engine/config.py
HistoryA few weeks of readings; the model is trained on the plant's own data

Limitations
  • SolarSense is an installable app (PWA): one code base runs on laptop and phone. Plant data is never stored offline — it always comes fresh from the engine.
  • Login uses DEMO accounts: passwords are stored only as salted hashes, sessions last 8 hours and end when the server restarts. On the static demo copy the login is for show only.
  • Only a few weeks of data from one season (May–June); accuracy in winter or monsoon is unknown.
  • One weather sensor per plant: a cloud over one corner of a plant can look like a fault there. Comparing each inverter with its neighbours reduces this.
  • No cloud sensor and no GPS: the sky (clear → overcast) is read from the sunlight against a clear-sky curve learned from the brightest days — an estimate, not a measurement. The temperature effect is measured from our data; for Plant 2 it is weak evidence.
  • No official fault labels exist, so we validated with faults we planted ourselves (results in reports/metrics.json → validation).
  • Plant 1's DC power was rescaled because the raw values were physically impossible (see assumptions below).
  • The ₹ figures use an assumed tariff (configurable) until the team cites a sourced one — see Assumptions below.
  • Small underperformance is usually not caught, by design, to avoid false alarms.
